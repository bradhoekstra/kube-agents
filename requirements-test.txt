# The third-party imports the modules under `make test-python` actually need.
# The admin console keeps its application and test dependencies in its own
# requirements file; the remaining packages below are what the agent scripts
# import at module scope, so without them the test modules that import those
# scripts fail to load at all. Everything else in the suite is stdlib unittest.
#
# This file is the single source of truth for the list. Every installer reads
# it -- `make test-python-deps` locally, and in CI both
# .github/workflows/python-tests.yml, which pins its Python, and
# .github/workflows/k8s-operator-test.yml, which takes the runner's default --
# because a hand-copied second list is how they drift into a suite that passes
# on a runner and cannot be run on a laptop. No other workflow installs this
# file; the ones on other Python versions install pyyaml or
# tests/e2e/requirements.txt, neither of which pulls in anything below.
#
# Deliberately unpinned apart from the one constraint that matters. These stand
# in for what the runtime image gets transitively from hermes-agent
# (deploy/docker/Dockerfile), which is far too heavy to install for a unit-test
# run, so pinning them here would be pinning a fiction rather than what ships.
#
# If the install fails with "No matching distribution found for mcp<2", pip is
# pointed at a mirror that does not carry it -- check `pip config debug`. The
# package is on PyPI, so the fix is to name the index for this one install
# rather than to reconfigure the machine:
#
#     python3 -m pip install --index-url https://pypi.org/simple -r requirements-test.txt

-r admin_console/requirements.txt

# session_kv_server.py imports FastAPI at module scope. The console's file
# already pins it, but the agent-side suite states the dependency itself so a
# change to the console's requirements cannot silently break it.
fastapi

# agent_common_server.py, platform_mcp_server.py and router_server.py all do
# `from mcp.server.fastmcp import FastMCP`. 2.x deletes that module in favour
# of `mcp.server.mcpserver.MCPServer`, a rewrite rather than an import change,
# so the ceiling holds until those three are ported. It bounds the package and
# not the interpreter -- 1.x and 2.x both declare requires-python >=3.10 and
# ship one pure-Python wheel -- so it rules out no Python version CI runs.
mcp<2

python-dotenv
pyyaml
